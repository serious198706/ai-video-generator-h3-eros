# 实现与验收计划

日期：2026-10-29。以下是完整验收路线。首版代码及本地验证已完成，阶段 1 的 GPU 环境安装、阶段 2 的真实权重数值验证、阶段 3 的 GPU 成片与阶段 5 的云端部署尚未执行，详见 VALIDATION.md。

## 阶段 1：锁定上游与可运行环境

产物：独立环境安装脚本、来源清单、依赖锁、模型 manifest、下载校验和 preflight。

1. 取得 Space 完整 commit 和所需文件，审查 import 副作用、许可证及外部调用。
2. 阅读固定 Diffusers 版本的 H3 block 和 conditioner 实现，确认编码接口和本地加载方式。
3. 核对 GPU、驱动、CUDA wheel、Python、RAM、磁盘空间；独立创建环境，不修改 Wan 环境。
4. 固定基础仓库 revision 和 Eros revision；按组件下载，避免无用 reference 副本；校验 Eros SHA-256。
5. 保存真实安装结果。requirements 中的候选版本只有完成安装、导入、最小组件构造后才变成经过验证的锁。

门槛：离线缓存加载能够复现；缺文件、错误哈希、版本不兼容时明确失败。健康检查不等同于模型就绪。

## 阶段 2：转换和条件编码

产物：`infer/eros.py`、pipeline 适配、本地 conditioner、CPU 单测、转换报告。

- 移植必要的键转换，添加覆盖清单和严格缺项检查；保留所需基础 time embedder。
- 单测验证非对称小张量的 QKV、gate/value 变换，避免测试数据对称而掩盖排列错误。
- AdaLN 测试覆盖 bias、basis、mean，比较参考计算与展开结果。
- 在真实 checkpoint 上记录 dtype、覆盖数、非有限值检查和关键层数值误差；不输出权重内容。
- 编码器实现输入规范化及 safetensors 输出；测试首尾图在两侧预处理一致。
- 单卡调度显式管理模型上/下 GPU；记录搬运前后真实空闲显存。释放失败则回收子进程，不能继续叠加载模型。

门槛：可在同一台机器完成“条件编码 → 释放编码 GPU → 生成组件加载”，并且没有隐式请求公共 Space。

## 阶段 3：真实 GPU 最小闭环（先于云端接单）

产物：CLI 生成入口、MP4、抽帧、音轨检查、JSON benchmark 报告。

首个样例固定普通人物/风景图片与非敏感提示词、seed=42、540p 档、5 秒请求、6 步、额外 LoRA 关闭、AoTI 关闭、无量化。调用接口和样例输入都写入报告，但不保存凭证或临时签名 URL。

验收：

- 实际宽高、124 帧、24 fps 与输出一致；音视频时长及轨道可由 ffprobe 检查。
- 生成帧无 NaN/Inf、空帧或整段全零；音频非有限值、削波和异常静音有检查结果。
- 人工看运动、主体一致性、首尾图引导、画面闪烁及音画同步；数值检查不能替代画质验收。
- 记录加载、编码、搬运、去噪、解码、封装耗时，所有相关进程的 GPU 峰值和主机内存。
- 至少两次连续任务通过，检查 CPU/GPU 内存是否持续增长。

然后扩展到横竖画布、720p、2/14 秒边界、首尾帧和有/无音轨组合。未通过的组合不加入生产能力列表，不能失败后悄悄降分辨率或改步数。

如转换后结果异常，使用最小 reference 运算或兼容原生工作流诊断同一权重和输入。无需先部署整套 ComfyUI；但不能以“Space 也是这样写的”代替定位。

门槛：目标 GPU 上实际生成成功且画质验收通过；CPU mock 和占位视频不能满足本阶段。

## 阶段 4：异步服务与故障恢复

产物：独立 Lambda 包、worker、SQS 消费、S3 状态、回调及本地替身集成测试。

重点测试：

| 场景 | 预期 |
| --- | --- |
| 不支持的时长/画布/参数 | 入队前 422，消息数不变 |
| S3 状态读取故障 | 退避，不冒充任务不存在 |
| 重投次数达到上限但已有成功终态 | 保留成功，不覆盖为 poisoned |
| 编码、推理、上传分别失败 | 阶段和错误码准确；资源清理完成 |
| 上传成功后终态写入失败 | 不删除消息；重投走结果恢复校验 |
| 终态成功但回调失败 | 只补回调，不再生成 |
| 回调成功后进程崩溃 | 允许重复通知，业务按 task_id 幂等 |
| SIGTERM / 长时间任务 | 停止接新单；当前任务按退出预算收尾或等待重投 |
| 续租失败 | 记录失去执行安全性的风险，停止启动新任务；不宣称具备全局排他 |
| 状态 heartbeat 与终态并发 | 终态不被旧快照覆盖 |

下载校验包括 HTTPS、DNS/IP 限制、重定向逐跳检查、大小/超时/解码像素限制。回调沿用明确允许的内网策略，拒绝链路本地地址。无需访问真实业务回调即可完成本地测试。

门槛：服务测试使用本地 SQS/S3 替身通过，Lambda 打包不包含 GPU 依赖，业务字段与状态约定一致。

## 阶段 5：部署与上线验收

产物：部署脚本、启动脚本、配置模板、操作说明、已验证能力清单、测试报告。

- H3 单独队列、独立 S3 prefix、独立运行目录和日志；部署前核对目标资源。
- GPU 预加载完成、权重校验和编码组件可用后才 `/ready=200` 并开始消费。
- staging 完成一次提交、生成、上传、查询、回调闭环，以及进程重启恢复演练。
- 验证队列积压、依赖故障、GPU OOM、回调耗尽能够从日志和状态定位。
- 记录实际支持的最大画布/时长，按最坏耗时配置 visibility、续租和 stalled 阈值。
- 固定经过验证的 release；回滚先停止接单并处理进行中任务，再恢复上一版本及配置。

首版完成标准：真实 GPU 成片验收和异步服务闭环都通过，并交付可重复安装、启动、查询、排错的实现。仅写出接口、mock 通过或服务进程存活都不算完成。

## 后续优化（不阻塞首版正确性）

1. 离线转换保存 Diffusers Eros 权重，减少启动磁盘读取和转换开销。
2. 对比单卡搬运与自有独立 conditioner GPU 的整单成本、延迟。
3. 逐项验证 AoTI、attention 后端、量化及新模型版本，每次只改变一个变量。
4. 多 worker 扩容前补外部任务租约和 fencing，并做重复投递/失去租约故障测试。

性能报告固定模型版本、输入、seed、画布、帧数和步数；分别报告冷启动与稳定态。不得把基础 H3 的 30 步测量按比例当作 Eros 6 步成绩。
